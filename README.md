# Simple Workflow

在本地 WebUI 编排审查、修复和复审 Agent，使用 DeepSeek Flash 审查真实项目。支持固定文件范围、条件分支、有限修复循环、逐次命令审核、确认或自动写回、备份撤销及 Markdown/JSON 报告。

当前 MVP 面向 **Linux、单用户、单个 Node.js 后台进程**。命令在项目副本内以本机用户权限运行，**未启用文件与网络隔离（AC-10 延期）**。只用于信任的项目和经逐次批准的检查；副本、白名单及审核不能限制进程访问宿主文件和网络。

## 启动与 `.env.local`

本次验证环境为 Node.js 24、pnpm 12。在项目根目录建立 `.env.local`：

```dotenv
DEEPSEEK_API_KEY=替换为你的实际密钥
# 可选：专用运行数据目录，不能位于被审查项目内，也不能包含被审查项目
# SIMPLE_WORKFLOW_DATA_DIR=/home/你的用户名/.local/share/simple-mutiagent
```

变量名必须是 `DEEPSEEK_API_KEY`，不能加 `NEXT_PUBLIC_` 前缀。不要把密钥发到聊天、写入工作流或提交 Git；`.env.local` 已被忽略。配置或修改后重启服务；未配置时，“运行设置”显示缺少密钥及配置方法，不展示密钥内容。未配置仍可编辑工作流和运行合成演练。

```bash
pnpm install
pnpm dev
```

打开 <http://127.0.0.1:3000>。生产启动：

```bash
pnpm build
pnpm start
```

开发和生产脚本只监听回环地址。API 校验本地 Host、同源来源、会话和修改操作令牌。不要将其作为公共服务或以多个后台进程运行。默认 Turbopack 构建已通过，旧缓存故障说明见[构建记录](.agents/docs/implemented/bug-fix/2026-10-14-turbopack-cached-port-permission-error.md)。

## 使用流程

1. 输入项目绝对路径，“浏览目录”或“打开项目”，勾选文件或目录。运行时固定范围、排除规则、工作流及原内容基线。允许读取未勾选关联文本，但不能修改；勾选目录允许新增/删除其内普通文本，单选文件不扩大到同目录。
2. 选择“完整流程”或“仅审查”模板。拖动、连线、添加或删除七种预置节点；点击节点配置提示词、模型、思考开关/档位、输出预算、输入引用及修复轮数。默认最多 1 轮，可配置 1–5 轮。
3. 条件分支通过配置 JSON 设置有序条件，字段为 `blockingCount`、`validationComplete`、`testsPassed`，保留 `fallback`。校验定位非法节点和连线，后端再次校验后才能启动。保存/加载使用本地 `workflow.json`；导入/导出只含配置与位置。
4. 选择“确认后写入”或“自动写入”，启动真实工作流。应用提交的补丁先写入副本，原项目在最终应用前保持基线；本机命令可能产生事务之外的副作用。
5. 每条命令单独暂停审核，展示实际程序、参数、目录、节点、版本、用途、产物和内容哈希。自动写入模式也必须逐次审核。拒绝不启动进程，必要验证缺失停止应用；断开最后一个事件连接、取消或会话失效使待审请求过期。
6. 查看节点输入/输出、每轮和最终差异及剩余问题。确认模式点击“确认应用最终差异”；自动模式在正常结束且验证完整后整批应用，仍有问题时保留结论。失败、取消、越界或缺失必要验证不会自动写回。
7. 应用前检查整个副本基线，任一原文件冲突整批停止。应用后可“撤销本次应用”；任一后续编辑冲突整批停止撤销。应用失败修正外部冲突后可再次确认，重新预检；有 `needs_recovery` 的事务须先人工恢复。
8. 导出报告或查看本地历史。刷新可以恢复选中的快照；后台重启只恢复历史查看、已完成事务撤销或保留副本的确认，不能续跑模型或命令。“重新运行”建立新副本、新基线和新审核。

## 工作台界面

顶栏在“流程编辑”和“运行历史”之间切换；右上角可选择跟随系统、浅色或深色主题，刷新后保留主题偏好。编辑页左侧“工作区”用于项目与文件范围，“节点库”用于添加节点；点击画布节点，在右侧修改配置。

点击“运行设置”后，右侧切换为下一次运行配置，选择真实工作流或合成演练、场景及写入模式。启动条件不足时按钮下方说明原因。返回节点配置不会丢失运行设置；切换历史也保留当前流程草稿及运行连接。

底部结果区域提供执行记录、选中节点输入／输出、各轮与最终差异，可展开或收起。运行操作和报告导出位于结果工具栏；待审核命令始终独立显示，收起结果或切换历史不会隐藏批准／拒绝入口。点击历史“查看”展开对应结果；删除历史与备份仍须明确确认失去撤销能力。

平板通过画布左侧按钮打开资源抽屉；手机另提供“配置”入口，两侧面板全屏显示。手机展开结果时进入全屏结果视图，点击收起或按 Escape 返回画布。抽屉支持键盘焦点约束及关闭后恢复，界面尊重系统减少动效偏好。

界面文案仅保留操作入口、必要的输入提示、启动条件、运行状态和审核详情。顶栏不再常驻模型调用与执行环境说明，节点卡片不重复模型说明，节点库不展示技术限制清单；这些信息在本文中维护。命令审核仍显示运行模式、程序及参数、目录、节点、轮次、版本、用途、预计产物、环境和内容哈希，删除备份仍须明确确认。文案精简不改变执行权限、模型调用、逐次审核或写入条件。

主题、组件、状态及文案维护约束见[工作台 UI 实现记录](.agents/docs/implemented/feature/2026-10-14-workflow-studio-ui.md)。

## 支持的文件与检查

副本只复制普通 UTF-8 文本。默认排除 `.git/`、`node_modules/`、`.next/`、`dist/`、`build/`、`coverage/`、`.env*`、私钥/证书和常见二进制；`node_modules/` 及运行 HOME/TMP 目录始终排除。修改其他排除规则后须重新打开项目；取消敏感文件排除会允许其内容被发送给 DeepSeek。

启动时固定命令白名单：最多 30 个发现的 `.test/.spec.[cm]js/ts` 文件以 Node `--test` 运行，以及可找到 npm 时已声明的 `test/check/lint/typecheck/build` 脚本。不接受自由 Shell，也不自动安装依赖。npm 的离线标志不限制脚本联网。副本不携带 `node_modules`；缺失模块/程序会记录为验证不可用，其他测试失败如实记录。需要依赖的完整工程检查通常无法在当前副本中完成；首版提供无需第三方依赖的[示例](docs/examples/README.md)。

副本最多 1000 文件、16 MiB 文本、1 MiB/文件；单次读取 256 KiB、节点读取总量 512 KiB。每节点最多 21 轮模型请求、20 次工具调用（失败/拒绝计入），输入历史最多 64 KiB，输出按节点配置（默认 8192 tokens）。每节点 10 分钟（含审核等待），模型请求及命令各 120 秒；429/5xx 最多尝试 3 次，命令每路输出最多 1 MiB并显示截断。命令使用最小环境，不主动注入密钥；Linux 进程组取消不能约束主动脱离进程组的脚本。

## 本地记录与恢复

数据默认保存在 `~/.local/share/simple-mutiagent/`；文件权限 `0600`、目录 `0700`：

| 路径 | 内容 |
| --- | --- |
| `workflow.json` | 工作流草稿 |
| `runs/<id>.json` | 快照、节点结果和审核 |
| `events/<id>.jsonl` | 有序事件 |
| `reports/<id>.md`、`diffs/<id>.json` | 报告与最终差异 |
| `baselines/<id>.json` | 私有原始文本基线 |
| `copies/<id>/` | 活动、失败或待确认副本 |
| `transactions/<transaction-id>.json` | 应用日志与原内容备份 |

历史手动保留，进程最多加载 50 次运行。已成功完成并应用/无差异的副本会清理；失败与等待确认副本保留。“删除历史与备份”须明确确认失去撤销能力，并清理该运行的全部事务；未解决恢复事务不能删除。

多文件写入不是系统原子事务。若后台在应用、回滚或撤销中退出，事务标为 `needs_recovery`，不会重放或覆盖文件。同工作区新应用被阻止；先停止其他编辑，按日志的 `changes`、`processed`、`recovered` 与当前文件逐项核对，保留日志副本后人工恢复。具体步骤见[完整实现记录](.agents/docs/implemented/feature/2026-10-14-simple-workflow-mvp.md)。撤销只覆盖登记的文本变更，不覆盖命令修改的其他宿主文件。

## 验证

```bash
pnpm test                 # 文件、事务、真实本机进程、模型协议替身、图和状态机
pnpm typecheck
pnpm lint
pnpm build
pnpm test:integration     # 已构建 Next.js 的真实 HTTP，含重启与历史恢复
pnpm test:deepseek        # 需要密钥，最小官方联网调用，有 API 用量
pnpm test:live            # 需要先 build；五种真实联网场景，自动批准临时示例检查
```

`test:live` 只操作临时示例副本，结束清理，并更新[报告样例](docs/examples/reports/live-verification.json)。自动化脚本的批准是验收夹具；正常界面仍逐次人工审核。合成演练始终明确标记，不作为真实模型或进程证据。模型调用次数与费用会变化，usage 缺失或失败结果未知时不估算账单。

UI 重写后，59 项单元测试、9 项 HTTP 集成测试、类型检查、lint 和生产构建通过；Chromium 验证双色主题、三种屏幕尺寸、流程编辑和合成运行／审核／历史操作。本轮使用独立临时项目与数据，不调用付费模型。此前五种真实联网场景及旧界面的验收范围见[原 MVP 记录](.agents/docs/implemented/feature/2026-10-14-simple-workflow-mvp.md#交付与验证证据)，此次 UI 证据见[工作台记录](.agents/docs/implemented/feature/2026-10-14-workflow-studio-ui.md)。

实现范围、AC-01–AC-18 证据与取舍见[完整 MVP 实现记录](.agents/docs/implemented/feature/2026-10-14-simple-workflow-mvp.md)，AC-10 延期及恢复条件见[隔离范围决定](.agents/docs/implemented/feature/2026-10-14-simple-workflow-mvp.md#隔离延期与恢复条件)。
