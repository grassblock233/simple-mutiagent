# Simple Workflow

在本地 Web 界面编排审查、修复和复审 Agent，通过 DeepSeek Flash 处理真实项目。工作流支持文件范围选择、条件分支、有限修复循环、逐次命令审核、确认或自动写回，以及备份撤销和 Markdown/JSON 报告。

项目面向 Linux、单用户和单个 Node.js 后台进程。源码会通过 DeepSeek API 处理。检查命令在项目副本内以本机用户权限运行，未启用文件与网络隔离；副本、白名单和人工审核不能限制进程访问宿主文件或网络。请只用于信任的项目，并逐次确认检查命令。

## 启动

已验证的环境为 Node.js 24、pnpm 12。在仓库根目录创建 `.env.local`：

```dotenv
DEEPSEEK_API_KEY=替换为你的实际密钥
# 可选：专用运行数据目录
# SIMPLE_WORKFLOW_DATA_DIR=/home/你的用户名/.local/share/simple-mutiagent
```

数据目录与被审查项目必须分离，不能互相包含。密钥变量不能加 `NEXT_PUBLIC_` 前缀，也不要写入工作流或提交 Git；`.env.local` 已被忽略。修改配置后需重启服务。没有密钥时仍可编辑工作流，启动运行则必须配置密钥、打开项目并选择文件范围。

```bash
pnpm install
pnpm dev
```

打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。生产运行使用：

```bash
pnpm build
pnpm start
```

开发和生产脚本只监听回环地址。API 校验本地 Host、同源来源、会话和修改操作令牌。请勿将服务公开到网络或以多个后台进程运行。

## 使用

1. 输入项目绝对路径，浏览目录并打开项目，勾选文件或目录。未勾选的关联文本可供读取，不能修改；勾选目录允许在其内新增、修改和删除普通文本，单选文件只授权该文件。
2. 选择“完整流程”或“仅审查”模板。在画布上添加、拖动和连接七种预置节点，点击节点配置提示词、模型、思考模式、输出预算和输入引用。修复默认最多 1 轮，可设为 1–5 轮。
3. 选择“确认后写入”或“自动写入”，启动工作流。启动时固定文件范围、排除规则、工作流和原内容基线；运行期间的配置编辑只影响下一次运行。
4. 审核每条检查命令，查看程序、参数、目录、节点、轮次、版本、用途、预计产物、环境和内容哈希。自动写入模式也需要逐次批准；拒绝不会启动进程。取消、会话失效或最后一个事件连接断开时，待审请求过期。
5. 查看节点结果、各轮及最终差异和剩余问题。确认模式需点击“确认应用最终差异”；自动模式在正常结束且验证完整后整批应用，仍有问题时保留审查结论。
6. 应用后可撤销本次修改，也可导出报告或查看历史。“重新运行”建立新副本、新基线和新审核，不复用批准记录。

条件节点通过 JSON 配置有序条件，支持 `blockingCount`、`validationComplete`、`testsPassed`，并须保留 `fallback`。界面定位配置错误，后端再次校验后才允许启动。保存和加载使用 `workflow.json`，导入和导出只包含配置与节点位置。

### 验证与写回

Agent 提交的补丁先写入副本，最终应用前原项目须与启动基线一致；获批的本机命令仍可能直接修改原项目或其他宿主文件，这些副作用不受副本约束。

必要检查按命令身份和最终代码版本核对。代码变化后须重新检查，另一条成功检查不能替代缺失的检查；同一版本任一必要检查失败或缺失均阻止应用。运行失败、取消、越界或必要验证未完成时，不会自动写回。

应用前检查整个原内容基线，任一冲突都会停止整批写入。修正冲突后可再次确认，系统重新预检。撤销前检查应用后的内容，任一后续编辑冲突都会停止整批撤销。标记为 `needs_recovery` 的事务须先人工恢复。

## 工作台

打开页面先进入欢迎工作台，可打开本地项目、创建完整／仅审查流程、继续编辑或查看历史。左侧图标栏切换欢迎页、项目文件、节点库和运行历史，底部提供运行设置；右上角保留系统、浅色或深色主题选择。

编辑页采用紧凑的桌面工作台布局：左侧资源面板、中间工作流画布、右侧节点配置／运行设置，中间下方为执行结果。项目文件按可折叠目录树展示；折叠不改变选择，选择目录后其后代显示为已授权且不能单独取消。启动条件不足时，运行按钮下方说明原因。

左右面板和底部结果均可收起。拖动分隔线调整宽度或高度，也可用 Tab 聚焦分隔线后按方向键调整，Shift 加速，Home／End 调整到当前最小／最大尺寸。存储可用时，尺寸和显隐保存在本机浏览器，可通过顶栏“重置布局”恢复默认；缩小窗口会限制面板尺寸以保留画布空间。较高窗口的结果高度刷新后可能缩小，最低支持尺寸内也存在收起工具栏遮挡，见[已知布局限制](.agents/docs/implemented/feature/2026-10-18-desktop-workbench.md#已知限制与缺陷)。

底部结果区域显示执行记录、节点输入／输出和差异。待审核命令独立显示，收起结果或切换欢迎页、历史页仍可批准或拒绝。切换视图保留流程草稿、画布视口、未提交的节点 JSON 配置和运行连接。点击历史“查看”展开对应结果。

界面仅在移动端视图（浏览器内容区宽度小于 768px）显示限制提示，不设窗口高度门槛；宽度达到 768px 的桌面或平板视图可继续操作。移动端视图下需加宽窗口后处理审核；后台仍保留运行状态和事件连接。刷新页面重新显示欢迎页，并按现有规则恢复上次运行显示；工作流草稿仍需主动保存。界面遵循系统减少动效偏好。

## 文件与检查限制

副本只复制普通 UTF-8 文本。默认排除 `.git/`、`node_modules/`、`.next/`、`dist/`、`build/`、`coverage/`、`.env*`、私钥、证书和常见二进制。`node_modules/` 及运行 HOME/TMP 目录始终排除；调整其他排除规则后须重新打开项目。取消敏感文件排除会允许其内容发送给 DeepSeek。

命令白名单在启动时固定，包括最多 30 个发现的 `.test/.spec.[cm]js/ts` 文件（以 Node `--test` 运行），以及找到 npm 时项目已声明的 `test/check/lint/typecheck/build` 脚本。不接受自由 Shell，不自动安装依赖，副本也不携带 `node_modules`。缺失模块或程序记为验证不可用，其他执行失败如实记录。依赖第三方包的完整工程检查通常无法在副本中完成，可先使用[无第三方依赖的示例](docs/examples/README.md)。npm 离线标志不能限制项目脚本联网。

| 项目       | 限制                                                                               |
| ---------- | ---------------------------------------------------------------------------------- |
| 副本       | 最多 1000 个文件、16 MiB 总文本、1 MiB/文件                                        |
| 读取       | 单次 256 KiB，每节点累计 512 KiB                                                   |
| 模型与工具 | 每节点最多 21 轮模型请求、20 次工具调用，失败和拒绝也计入                          |
| 输入与输出 | 输入历史最多 64 KiB，输出由节点配置，默认 8192 tokens                              |
| 耗时       | 每节点 10 分钟，含审核等待；每次模型请求和命令各 120 秒                            |
| 重试与日志 | 模型请求遇到 429/5xx 最多尝试 3 次；命令标准输出和错误输出各最多 1 MiB，截断会标明 |

命令使用最小环境，不主动注入密钥。Linux 进程组用于取消和超时清理，无法约束主动脱离进程组的程序。

## 记录与恢复

运行数据默认保存在 `~/.local/share/simple-mutiagent/`，也可通过 `SIMPLE_WORKFLOW_DATA_DIR` 指定。文件权限为 `0600`，目录为 `0700`。日志、差异、基线和备份可能包含源码，应按敏感材料管理。

| 路径                                 | 内容                   |
| ------------------------------------ | ---------------------- |
| `workflow.json`                      | 工作流草稿             |
| `runs/<id>.json`                     | 快照、节点结果和审核   |
| `events/<id>.jsonl`                  | 有序事件               |
| `reports/<id>.md`、`diffs/<id>.json` | 报告与最终差异         |
| `baselines/<id>.json`                | 原始文本基线           |
| `copies/<id>/`                       | 活动、失败或待确认副本 |
| `transactions/<transaction-id>.json` | 应用日志与原内容备份   |

刷新页面可恢复选中的运行快照。后台重启只恢复历史查看、已完成事务的撤销，以及保留副本的应用确认，不续跑模型或命令。

历史由用户手动清理，进程最多加载 50 次运行，达到上限仍可删除未加载的历史。成功完成且已应用或无差异的副本会清理，失败和等待确认的副本保留。“删除历史与备份”会清理该运行的全部事务，须明确确认失去撤销能力；存在未解决恢复事务时禁止删除。

历史列表及恢复、重试接口只接受真实运行记录。兼容性处理保留磁盘上的演练记录，不展示、不加载，也不转换成真实结果；如需清理，须在数据目录手动处理。

多文件写入不是系统原子事务。后台在应用、回滚或撤销中退出时，事务标为 `needs_recovery`，系统不重放写入，并阻止同工作区继续应用。恢复时先停止其他编辑，保留日志和受影响文件副本，再核对 `changes`、`processed`、`recovered` 与实际内容。具体步骤见[事务恢复说明](.agents/docs/implemented/feature/2026-10-14-simple-workflow-mvp.md#应用事务回滚撤销和中断恢复)。撤销只覆盖登记的文本变更，不能恢复命令造成的其他宿主副作用。

## 验证

本地检查无需调用付费模型。HTTP 集成测试需要先完成构建：

```bash
pnpm test
pnpm typecheck
pnpm lint
pnpm build
pnpm test:integration
```

单元测试覆盖文件、事务、本机进程、模型协议、图和状态机。HTTP 集成测试在临时项目中使用正式 API、实际工具和本机进程，通过测试子进程预加载模型响应替身，覆盖审核、应用、撤销及后台重启恢复。测试替身不属于产品运行入口，也不能作为官方模型联网证据。

以下检查需要配置密钥，会产生 API 用量：

```bash
pnpm test:deepseek        # 最小官方请求，要求响应为 OK
pnpm test:live            # 先 build；五种联网场景，自动批准临时示例检查
```

`test:live` 使用临时示例副本，结束后清理，并更新[联网报告样例](docs/examples/reports/live-verification.json)。自动批准仅用于验收脚本，正常界面仍逐次人工审核。调用次数和费用会变化；用量缺失或失败结果未知时，报告不估算费用。
