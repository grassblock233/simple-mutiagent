# Agent Note: 只保留精简单轮修复模板

Status: implemented

## Problem

将单轮修复设为默认之后仍保留三套模板和选择菜单，入口与模板生成代码并未真正精简。用户进一步要求将当前精简流程作为唯一默认模板，删除原先模板。

## Decision

`createTemplate()` 只生成当前六节点单轮修复流程，不再接收模板类型。产品删除 `full`、`review` 生成分支和 `TemplateKind` 类型；欢迎页仅保留创建单轮修复流程，编辑页使用“加载默认模板”按钮代替模板菜单。

旧八节点循环和三节点审查图仅作为 `tests/legacy-workflow-fixture.ts` 中的兼容性夹具存在，不再向产品提供模板。循环上限、退出行为及旧工作流存储往返继续通过这些夹具验证。真实模型联调脚本统一创建当前默认流程，干净代码通过分支直接输出。

### 兼容边界

工作流格式 v1、执行引擎及节点库不变。已保存、导入、历史工作流不自动替换或重新布局，旧循环仍按自身配置运行。删除的是预置模板与生成 API，原 `createTemplate("full" | "review" | "single")` 调用须改为无参调用或直接提供工作流数据。

### 历史审计

本次检索与前序[单轮默认记录](2026-10-21-single-repair-default.md)相同范围的模板、画布决策。前序记录部分重叠，互链：本文取代其保留高级／仅审查预置模板的选择；布局、测量、端口显示及旧工作流兼容边界继续有效。MVP、工作台 UI、桌面工作台、真实工作流记录部分重叠，维持前序记录中的链接与职责；移动端和 Turbopack 记录无关。proposed/rejected 无相关提案，无完全吸收或待清理提案。

## Alternatives considered

- **仅隐藏旧菜单选项**：变更少且可以保留内部调用，但仍维护用户要求删除的产品模板；因此删除生成分支，仅在测试中保留旧图夹具。
- **同时删除循环运行能力**：可以继续缩减执行器，但会破坏已保存和导入工作流；本次只删除预置入口和模板生成 API，保留格式和运行兼容性。

## Consequences

所有新建和加载默认模板的入口都生成同一个六节点图。其他拓扑通过编辑、保存和导入继续使用；历史报告保留原始模板事实，不重新生成。

## Verification

后续测试精简与当前数量见[测试审查记录](../testing/2026-10-21-test-suite-trimming.md)；以下保留当次验证事实。

`pnpm test` 的 75 项测试、`pnpm lint`、`pnpm typecheck` 通过。浏览器确认欢迎页删除仅审查入口，编辑页只保留“加载默认模板”，加载后显示六节点、六条连线及校验通过。
