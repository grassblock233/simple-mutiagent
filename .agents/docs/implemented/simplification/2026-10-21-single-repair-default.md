# Agent Note: 默认单轮修复与从左向右的画布

Status: implemented

## Problem

原默认模板包含八个节点、两次条件判断和一个循环控制。首次使用需理解循环与轮数上限，蛇形布局又让执行路径回折。欢迎页和模板菜单各自替换工作流，菜单没有重置适配标记；复用节点 ID 时还可能沿用旧尺寸，导致新流程不能可靠地完整显示。

## Decision

后续用户决定只保留单轮修复预置模板，见[唯一模板记录](2026-10-21-single-template-only.md)；本文保留首次默认选择的理由和布局、兼容边界。

`createTemplate()` 默认生成 `single` 六节点模板。读取、审查、“有阻塞问题？”和输出在上行，修复、复审在下行；节点按执行顺序以 280px 横距、240px 行距向右排列。阻塞问题走修复和复审后直接输出；无阻塞问题跳过修复；复审仍有问题时也结束并报告，不自动重试。必要验证缺失沿用原引擎门禁，不继续修复或应用。

欢迎页使用“创建单轮修复流程”，菜单提供“单轮修复（默认）”“循环修复（高级）”“仅审查”。默认条件的卡片端口和连线分别显示“需要修复”“直接输出”，内部仍使用 `has_issues`、`fallback`；编辑后的条件或自定义条件显示原 ID。默认分支的直接输出端口位于修复端口上方，以分开两条路径；端口顺序变化时更新 React Flow 的内部锚点。

模板入口共用加载函数，清除旧选中连线及应用层尺寸缓存，并用新的 React Flow Provider 清除内部节点尺寸。新画布等待节点完成测量、编辑页可见后适配全图。普通欢迎页／编辑页／历史页导航保持画布挂载，不重新适配或丢失视口。保存加载和导入也使用统一的工作流替换函数，但保留读取到的节点与坐标。

### 兼容边界

- 工作流格式仍为 v1，执行引擎、验证门禁、运行快照和应用事务不变；单轮行为由图的连线实现。
- 显式 `createTemplate("full")` 仍返回原八节点结构、坐标、输入引用、循环配置、轮数上限和退出路径；`review` 仍为读取、审查、输出三个节点。
- 已保存、导入和历史工作流不自动替换、迁移或重新布局。新的默认值仅影响新建模板及无参数代码调用；内部端口名称不写入显示文案。
- 继续使用原 React Flow 和卡片，不引入布局依赖或组合节点。适配全图会缩小长流程；用户可放大或收起侧栏阅读。

## Alternatives considered

- **继续以八节点循环模板为默认**：保留现有入口和多轮能力，但首次使用仍需理解循环及蛇形路径，因此将它保留为高级选项。
- **只修改模板后调用适配**：代码较少，但相同节点 ID 会复用旧尺寸，适配可能早于新卡片测量；因此只在替换工作流时重建画布存储，并等待测量完成。
- **每次进入编辑页都适配全图**：能让模板可见，但会覆盖用户平移、缩放后的视口；因此适配只发生在首次显示和明确替换工作流后。

## Consequences

新建流程最多修复一次，剩余问题有明确终止结果；需要重复修复时显式选择高级模板。旧工作流继续按自身连线和循环配置运行，不能把新默认推广为对历史记录的全局执行限制。

画布替换清理临时选择和尺寸，同时不触碰工作区、执行连接或历史快照。未来新增模板入口必须复用同一替换逻辑，避免再次引入加载行为差异。

## Verification

后续测试精简与当前数量见[测试审查记录](../testing/2026-10-21-test-suite-trimming.md)；以下保留当次验证事实。

`pnpm test` 75 项通过；`pnpm lint`、`pnpm typecheck` 通过。三种模板均通过格式与语义校验；默认单轮覆盖无问题跳过修复、修复成功、复审仍有问题、初审及复审必要验证缺失；原循环专用测试显式使用 `full`，覆盖 1/2/5 轮上限与成功提前退出。模型、命令与文件事务测试继续使用既有测试夹具，本次不调用付费模型。

浏览器在 1440×1000、1920×1080 检查深浅主题、模板切换、节点拖动、连线选择、侧栏收起、全图适配及欢迎页往返；节点边界均在画布内，默认分支连线标签不覆盖节点。普通导航保留视口和拖动位置，重新加载模板清除旧连线选择。
