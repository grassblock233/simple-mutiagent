# Agent Note: 仅限制移动端视图

Status: implemented

## Problem

桌面工作台按 1100×680 限制整个界面，使较窄或较矮的桌面窗口也无法编辑和处理审核。用户要求降低限制，仅在移动端视图阻止操作。

## Decision

以浏览器内容区宽度小于 768px 定义移动端视图，不设窗口高度门槛，不按设备型号、User-Agent 或触摸能力判断。宽度达到 768px 即允许使用现有工作台。

移动端提示和工作台 `inert` 使用同一个 React 布尔状态；提示通过 `hidden` 显隐，避免 CSS 媒体查询与 JavaScript 尺寸判断不一致。移动端提示说明加宽至 768px 即可继续操作。视口变化不卸载工作台，也不改变运行订阅或布局存储。

- proposed、rejected 中没有相关提案。

## Alternatives considered

- **继续降低宽高双门槛**：能避免部分拥挤布局，但窗口高度仍会阻止正常桌面操作，不符合仅限制移动端视图的要求。
- **按设备类型判断**：能区分手机与桌面硬件，但无法准确表达当前视图宽度，也会将窗口缩放和设备识别混为一谈，因此使用单一宽度断点。

## Consequences

1000×650 等桌面小窗口可以继续操作和审核；较矮窗口不再出现全屏限制。窄窗口仍沿用现有面板尺寸和收起能力，完整三栏体验建议保留更大空间。小于 768px 时审核仍需加宽窗口；不新增移动端布局。结果栏换行、较高窗口恢复和多触点拖动等旧问题不在本次修改范围。

## Verification

本轮 `pnpm typecheck`、`pnpm lint`、`pnpm build` 和 `git diff --check` 通过。浏览器验证 1000×650、1100×500、768×600 时提示隐藏、工作台没有 `inert`，1000×650 可编辑名称及切换面板；767×900、390×844 时提示显示、工作台设为 `inert`。恢复到 768px 后仍可编辑。页面根节点没有横向溢出，浏览器没有记录页面错误。检查未调用模型，未重新执行不受此次界面门槛修改影响的完整 HTTP 集成测试。
