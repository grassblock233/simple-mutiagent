# Agent Note: 移动端视图门槛

Status: implemented

## Problem

桌面工作台按 1100×680 限制整个界面，较窄或较矮的桌面窗口无法编辑和审核。门槛只应阻止移动端视图，不限制桌面窗口。

## Decision

2026-10-25 的后续边界与变更见[大项目、草稿与上下文记录](2026-10-25-large-project-draft-context.md)；本文保留当时决定的背景与历史验收事实。

以窗口宽度小于 768px 定义移动端视图，不设窗口高度门槛，不按设备型号、User-Agent 或触摸能力判断。宽度达到 768px 即允许使用现有工作台。

移动端提示和工作台 `inert` 使用同一个 React 布尔状态；提示通过 `hidden` 显隐，避免 CSS 媒体查询与 JavaScript 尺寸判断不一致。提示说明加宽至 768px 即可继续操作，并建议使用桌面浏览器；该建议不参与判断，门槛只看宽度。视口变化不卸载工作台，也不改变运行订阅或布局存储。

## Alternatives considered

- **继续降低宽高双门槛**：能避免部分拥挤布局，但窗口高度仍会阻止正常桌面操作，不符合只限制移动端视图的目标。
- **按设备类型判断**：能区分手机与桌面硬件，但无法表达当前视图宽度，也会把窗口缩放和设备识别混为一谈，因此使用单一宽度断点。

## Consequences

1000×650 等桌面小窗口可以继续操作和审核；较矮窗口不出现全屏限制。窄窗口仍沿用现有面板尺寸和收起能力；窄画布低于 400px 目标，见[已知限制与缺陷](#已知限制与缺陷)。小于 768px 时审核需加宽窗口，且没有独立审核入口；不新增移动端布局。结果栏换行、较高窗口恢复和多触点拖动等未解决问题不在当前支持范围。

若默认三栏不可接受，须另行决定自动收起或提高门槛，见[桌面待办](2026-10-18-desktop-workbench.md#待办)。

### 已知限制与缺陷

- 768–917px 默认三栏画布约 250–399px，低于 400px 目标，详见[桌面布局记录](2026-10-18-desktop-workbench.md#已知限制与缺陷)；需收起一侧或加宽到 918px。
- 跨断点不主动迁移焦点；工作台变为 `inert` 后，当前焦点可能丢失，尚未实现焦点恢复。

## Verification

`pnpm typecheck`、`pnpm lint`、`pnpm build` 和 `git diff --check` 通过。2026-10-18 的浏览器验证覆盖 1000×650、1100×500、768×600：提示隐藏、工作台没有 `inert`；1000×650 可编辑名称及切换面板；767×900、390×844：提示显示、工作台设为 `inert`；恢复到 768px 后仍可编辑。

768×600 未测默认三栏画布宽度，也未做跨断点键盘焦点验证。页面根节点没有横向溢出，浏览器没有记录页面错误。检查未调用模型，也未重新执行与本门槛无关的完整 HTTP 集成测试。
