# Agent Note: 桌面 IDE 工作台布局

Status: implemented

## Problem

工作台缺少欢迎入口、可调整的面板尺寸和层级化文件浏览，项目文件只能按完整路径平铺。产品范围限定桌面视图：面板必须可收起、可拖动，并提供欢迎页和可折叠目录树；视觉参考桌面终端的紧凑分区与蓝色强调色。

## Decision

2026-10-25 的后续边界与变更见[大项目、草稿与上下文记录](2026-10-25-large-project-draft-context.md)；本文保留当时决定的背景与历史验收事实。

默认模板与模板加载的后续变更见[单轮修复默认模板记录](../simplification/2026-10-21-single-repair-default.md)；本文保留原决定的背景及其他边界。

工作台使用左侧图标导航、资源面板、中央内容、右侧配置和中央下方结果面板。首次打开进入欢迎页，支持打开项目、创建完整/仅审查模板、继续编辑和查看历史。选择模板替换当前流程，打开项目不替换流程；欢迎页和历史页隐藏编辑侧栏，返回编辑恢复原状态。

### 状态与接口边界

- `WorkflowStudio` 持有工作流、项目范围、运行快照和唯一 SSE 订阅。编辑画布、资源与配置组件保持挂载，通过 `hidden` 切换显示；因此导航不丢失画布视口和节点 JSON 草稿，也不导致审核过期。仅首次显示已测量画布时适应全部节点，普通导航不重置视口。
- 命令审核位于结果面板外，跨页面常驻。新审核展开结果；收起结果不影响批准/拒绝。运行、应用、撤销、历史清理及运行协议见[真实工作流记录](../simplification/2026-10-17-real-workflow-only.md)。
- 界面不提供终端、连接管理或文件编辑器。工作流导入导出、后端 API、版本与授权 schema 不包含布局状态。

### 布局、主题与支持范围

布局偏好独立存储在 `simple-workflow-layout-v1`：默认资源宽 260px、配置宽 300px、展开结果高 260px，左右显示、结果收起。资源宽 220–420px，配置宽 240–480px，结果高至少 140px；视口进一步限制尺寸，中央至少保留 400px 宽、160px 高。

768–917px 的默认三栏达不到该目标，需收起一侧或加宽到 918px，见[已知限制与缺陷](#已知限制与缺陷)。窗口尺寸变化只限制当前呈现，不覆盖已保存偏好；刷新读取仍有[结果高度截断缺陷](#已知限制与缺陷)，不能保证较高窗口的尺寸原样恢复。

使用 `useSyncExternalStore` 提供稳定服务端快照、浏览器存储恢复及窗口变化订阅；坏 JSON、无效类型或不可用存储回退默认布局，存储失败后仍支持当前会话调整。分隔线采用 Pointer Capture 和可访问 separator，支持方向键、Shift 加速、Home/End；顶栏提供重置。

默认主题为 system，沿用 `simple-workflow-theme`、首屏主题脚本及 React Flow 的主题同步。深浅主题均采用蓝色强调色、细边框、小圆角和低阴影。全局 CSS 与 CSS Modules 的职责见[CSS Modules 记录](2026-10-14-workflow-studio-ui.md#css-modules)。

窗口宽度小于 768px 时进入移动端视图，工作台交互区域（包括审核按钮）由[移动端视图记录](2026-10-18-mobile-viewport-gate.md)设为 `inert` 并显示加宽提示；宽度达到 768px 时使用本文的桌面布局。视口变化不卸载执行状态、快照或连接。触屏支持需重新设计导航和画布操作；仅删除窗口提示不足以恢复。

### 目录树

从后端提供的平面文件路径在前端建立层级，目录优先并按名称排序。展开/折叠使用本地组件状态，不发送请求、不更改选择。目录授权仍允许范围内新增/修改/删除；继承父目录授权的后代勾选且禁用，部分后代被选时父目录显示半选。去掉父目录授权后，之前显式选择的后代仍保留，不能把半选显示误当作目录授权。

## Alternatives considered

- **仅更新视觉**：修改量小，但无法满足欢迎入口、目录树及面板调整需求，因此重组前端布局。
- **保留手机抽屉**：可继续提供小屏操作，但产品范围限定桌面视图，因此不提供小屏抽屉，只给出最低窗口提示。

## Consequences

布局偏好独立于业务协议，导航和尺寸调整不影响执行连接。桌面面板支持保存偏好，但刷新恢复受[已知限制与缺陷](#已知限制与缺陷)限制；移动端视图（宽度 < 768px）不提供工作台操作，窄窗口的可用画布见[已知限制与缺陷](#已知限制与缺陷)。目录树仍基于完整文件列表构建，不引入懒加载或编辑文件能力。

### 已知限制与缺陷

以下行为由浏览器检查或布局公式确认；未实施的修复方向见 [待办](#待办)。

| 场景 | 当前行为与影响 |
| --- | --- |
| 768–917px 三栏 | 默认左 220px、右 240px，画布约 250–399px，低于 400px 目标；可收起一侧或加宽到 918px。该宽度未在浏览器验收中测量。 |
| 1100×680 收起结果 | 1100×680，左 260px、右 382px、中央 400px 时，结果收起容器为 36px，工具栏换行后约 57.6px，运行状态被底栏遮挡。页面根节点没有溢出不能证明内部无重叠。 |
| 较高窗口刷新 | 1920×1440 中结果高度设为 616px，刷新后变成 454px；[布局读取逻辑](../../../../lib/studio/layout.ts)固定按 1920×1080 适配，较高窗口的结果高度偏好在读取时被截断。 |
| 多点触摸拖动 | [PanelResizer](../../../../components/panel-resizer.tsx) 未记录拖动发起者的 `pointerId`，后续触点可以覆盖起点或提前结束拖动；支持触摸的桌面设备上可能造成尺寸跳变，尚未通过浏览器多点触摸复现。 |

### 待办

- 768–917px 下自动收起一侧面板，保住 400px 画布。
- 768–917px 下把宽度门槛提高到 918px，避免默认三栏压到 400px 以下。
- 收起工具栏采用内容自适应高度或可达的单行布局。
- 将存储解析校验与实际窗口适配分开。
- 保存并校验活动触点，忽略后续触点。

自动收起或提高门槛涉及行为变更，须单独决定。修复后仍需验证该宽度的内容可见性、较高窗口尺寸的刷新往返，以及多点触摸下的拖动行为。

## Verification

2026-10-18 的检查：`pnpm typecheck`、`pnpm lint`、`pnpm build` 通过；`pnpm test` 的 70 项单元测试及 `pnpm test:integration` 的 12 项 HTTP 集成测试通过，未调用付费模型。新增 [studio 单元测试](../../../../tests/studio.test.ts)覆盖损坏的布局存储、窗口缩小时的中央空间与偏好保留、目录分组去重、父目录授权继承和路径前缀边界。

浏览器检查使用本机生产预览，覆盖以下交互。下列记录采集于移动端门槛变更前，作为桌面布局证据；窄画布宽度未测量，见[已知限制与缺陷](#已知限制与缺陷)。

- 1100×680、1440×900、1920×1080 的深浅主题均采集截图；含中文多级目录和较长文件名时，页面根节点没有横向或纵向溢出。结果面板内部、目录树和配置区域各自滚动。
- 欢迎页默认入口、完整/仅审查模板、打开项目、添加节点后自动配置；欢迎/历史往返保留当前工作流名称与未提交高级 JSON；历史隐藏侧栏，返回恢复编辑状态。
- 三处分隔线的指针拖动、方向键调整；显隐与尺寸刷新恢复、重置布局。恢复检查不包含对所有窗口尺寸的保证，较高窗口的反例见[已知限制与缺陷](#已知限制与缺陷)。
- 目录选择、继承授权、目录折叠后选择数量不变、重新展开后后代仍勾选且禁用。
- 保存/加载及导出后重新导入；导出仅含 `formatVersion`、`name`、`nodes`、`edges`，不含布局数据。
- 使用仓库[模型协议替身](../../../../tests/fixtures/model-transport.mjs)和测试专用哨兵密钥，在独立临时项目/数据目录完成模拟模型运行；未调用付费模型。
- 模拟运行中，新审核展开结果，收起结果、切换欢迎/历史保留审核；恢复桌面尺寸后批准本地测试，运行可继续，支持节点输入输出、各轮/最终差异、应用与撤销，并核对临时文件内容。另验证重新运行、欢迎页取消运行、历史刷新/查看和 JSON 报告下载。
- 历史删除与备份确认入口仍在，未勾选确认时删除按钮禁用；浏览器检查未实际删除历史，删除协议由 HTTP 集成测试覆盖。

焦点轮廓、键盘即时调整、pointer capture、忙碌反馈、短时颜色过渡及 reduced-motion 处理通过静态检查。

浏览器多点触摸和实际禁用 localStorage 时的异常回退尚未动态验证；存储回退仅有纯函数异常数据测试及存储访问 try/catch 的代码审查。

4 项 studio 测试都是辅助函数测试，未自动挂载组件；浏览器人工检查不能替代组件交互回归测试。
