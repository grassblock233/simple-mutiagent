# Agent Note: 画布中心工作台与双色主题

Status: implemented

## Problem

工作区、节点库、节点配置、运行设置和历史集中在三栏时，运行设置及历史需要在长表单底部寻找。硬编码的深色样式不能跟随系统，小屏缺少独立面板入口。工作台需要支持双色主题、画布中心布局和完整响应式操作，同时保留执行状态与审核入口。

## Decision

工作台的主题偏好、单一 SSE 订阅、审核边界与界面文案规则以本文为准；布局、响应式与移动端支持见[桌面工作台记录](2026-10-18-desktop-workbench.md)和[移动端视图记录](2026-10-18-mobile-viewport-gate.md)。

运行设置仅提供真实工作流，启动要求密钥、工作区和文件范围；运行入口见[真实工作流交付修正](../simplification/2026-10-17-real-workflow-only.md)。

### 状态与接口边界

- `WorkflowStudio` 持有工作流、工作区范围、选中节点、会话、运行状态及唯一 SSE 订阅。呈现组件接收状态和回调，不拥有独立执行器；切换导航通过隐藏编辑工作台保留画布视口、节点 JSON 草稿和面板内容。
- `WorkspacePanel`、`RunSettings`、`HistoryPanel`、`ExecutionPanel`、`ApprovalPanel` 分别承载资源、下一次运行、历史、结果与逐次审核。界面状态不进入工作流导出或后台 schema。
- 节点测量数据独立于 Workflow，选择、尺寸变化不改写业务节点。HTTP/SSE 快照用 `newestSnapshot` 防止迟到响应覆盖新事件。
- 布局与主题不改变工作流格式 v1、命令逐次审核、文件确认、撤销及删除备份确认。运行创建只接受真实运行请求。

### 主题与动效

主题选项为 system、light、dark，本地存储键为 `simple-workflow-theme`，默认 system。根布局的固定内联脚本在内容显示前设置 `data-theme`；客户端用 `useSyncExternalStore` 订阅存储变化和系统配色变化，服务端快照稳定，避免 hydration 内容分歧。存储不可用时主题选择在当前页面有效。React Flow 的模式与主题同步，所有画布表面和语义色通过 CSS 变量控制。

动效以 150ms 按压反馈为主，不打断画布编辑或键盘操作；减少动效模式关闭位移反馈。节点类型、端口及执行状态同时使用文字呈现，不能只依靠颜色。

### CSS Modules

全局 CSS 仅包含主题变量、基础控件及减少动效规则；工作台组件使用 CSS Modules。Turbopack 的 Tailwind 加载规则排除 `*.module.css`，让 Next.js 原生处理局部类和 `:global` 第三方选择器；不向 CSS Modules 加入 Tailwind 指令，避免加载器将局部样式当普通 CSS 转换。

### 界面文案维护

工作台只保留帮助当前操作的信息；模型调用方式、文件限制、执行环境与恢复边界集中在 [README](../../../../README.md) 维护。运行报告保留环境限制说明；常驻面板不重复展示同一段技术横幅。

- 顶栏不展示技术横幅、密钥状态徽标和 LOCAL 标识；节点卡片不展示模型与实现说明；节点库底部不设限制清单；画布不重复操作说明。循环节点展示最大修复轮数。
- 运行设置和历史页使用简短说明；成功通知使用简短结果，初始状态显示“就绪”，底部不展示协议版本。
- 保留真实运行未满足的条件、缺少密钥时的配置方法、排除规则重新打开项目才生效的提示，以及输入引用所需的格式与版本信息。
- 审核区域不设通用环境说明句，保留实际运行模式、程序、参数、目录、节点、轮次、版本、用途、预计产物、环境和内容哈希。批准/拒绝操作及其请求体不属于文案调整范围；删除历史与备份的明确确认保留。

添加文案时，先判断它是否帮助用户完成当前操作或理解当前结果。README 的实现说明不重复放在常驻面板；错误原因、启动条件、实际审核信息和会造成数据损失的操作确认不作为冗余说明删除。文案规则不改变执行权限、隔离能力或订阅生命周期。

## 历史

### 2026-10-14 布局与断点

2026-10-14 的布局采用“流程编辑 / 运行历史”主导航。编辑页左栏使用工作区、节点库两个标签；中央保留流程编辑和校验；右栏在节点配置与运行设置之间切换。执行结果默认收起，启动运行、出现新审核或查看历史时展开。审核信息位于稳定的运行区域，跨主视图显示，不随结果面板收起消失。

断点与抽屉：≥1200px 使用三栏；768–1199px 将资源栏改为抽屉；<768px 两侧栏均为全宽抽屉，执行结果在展开时占满屏幕。手机运行区域包含结果和审核，减少硬编码的遮挡补偿。

抽屉及手机全屏结果支持 Escape、焦点约束和可见触发器的焦点恢复。切换断点会移除不再适用的模态语义。触控控件至少 44px，输入框采用 16px 字号，容器使用 `100dvh` 和 safe-area。

## Alternatives considered

- **保留现有布局仅更新视觉**：改动较小，能保留已有位置记忆；运行设置和历史仍隐藏在表单深处，因此采用布局重组。
- **分步引导界面**：首次使用时更容易理解操作顺序；日常需要反复编辑和调试，画布与配置面板可随时切换更符合这一使用方式。
- **仅深色主题**：样式维护和验收成本更小；不能满足跟随系统双色主题的要求，因此提供系统/浅色/深色三态偏好。

## Consequences

功能位置更清晰，主题及响应式状态独立于执行协议。组件共用一个局部样式模块，减少视觉漂移；业务状态集中持有，因此拆分多个路由时必须重新处理草稿及订阅生命周期，不能把执行订阅放进可卸载的呈现组件。

移动端可完整配置、运行、审核和查看结果，但复杂画布仍需平移缩放；支持边界以桌面和移动端记录为准。不提供自动布局、执行隔离或模型供应商选择。
