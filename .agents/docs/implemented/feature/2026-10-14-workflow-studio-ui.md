# Agent Note: 画布中心工作台与双色主题

Status: implemented

## Problem

旧界面把工作区、节点库、节点配置、运行设置和历史集中在三栏中，运行设置及历史需要在长表单底部寻找。硬编码的深色样式不能跟随系统，小屏缺少独立面板入口。用户要求依据 Emil design engineering 技能重写界面，保留既有能力，采用双色主题、画布中心布局和完整响应式操作。

## Decision

工作台采用“流程编辑 / 运行历史”主导航。编辑页左栏使用工作区、节点库两个标签；中央保留流程编辑和校验；右栏在节点配置与运行设置之间切换。执行结果默认收起，启动运行、出现新审核或查看历史时展开。审核信息位于稳定的运行区域，跨主视图显示，不随结果面板收起消失。

### 状态与接口边界

- `WorkflowStudio` 持有工作流、工作区范围、选中节点、会话、运行状态及唯一 SSE 订阅。呈现组件接收状态和回调，不拥有独立执行器；切换导航通过隐藏编辑工作台保留画布视口、节点 JSON 草稿和面板内容。
- `WorkspacePanel`、`RunSettings`、`HistoryPanel`、`ExecutionPanel`、`ApprovalPanel` 分别承载资源、下一次运行、历史、结果与逐次审核。界面状态不进入工作流导出或后台 schema。
- 节点测量数据独立于 Workflow，选择、尺寸变化不改写业务节点。HTTP/SSE 快照仍用 `newestSnapshot` 防止迟到响应覆盖新事件。新审核自动关闭小屏资源／配置抽屉并展开结果，之后用户可以收起结果继续编辑。
- HTTP 路由、请求体、工作流格式 v1、命令逐次审核、文件确认、撤销及删除备份确认保持原有协议和条件。

### 主题与布局

主题选项为 system、light、dark，本地存储键为 `simple-workflow-theme`，默认 system。根布局的固定内联脚本在内容显示前设置 `data-theme`；客户端用 `useSyncExternalStore` 订阅存储变化和系统配色变化，服务端快照稳定，避免 hydration 内容分歧。存储不可用时主题选择在当前页面有效。React Flow 的模式与主题同步，所有画布表面和语义色通过 CSS 变量控制。

全局 CSS 仅包含主题变量、基础控件及减少动效规则；工作台组件使用 CSS Modules。Turbopack 的 Tailwind 加载规则排除 `*.module.css`，让 Next.js 原生处理局部类和 `:global` 第三方选择器；不向 CSS Modules 加入 Tailwind 指令，避免加载器将局部样式当普通 CSS 转换。

≥1200px 使用三栏；768–1199px 将资源栏改为抽屉；<768px 两侧栏均为全宽抽屉，执行结果在展开时占满屏幕。手机运行区域包含结果和审核，减少硬编码的遮挡补偿。抽屉及手机全屏结果支持 Escape、焦点约束和可见触发器的焦点恢复。切换断点会移除不再适用的模态语义。触控控件至少44px，输入框采用16px字号，容器使用 `100dvh` 和 safe-area。

动效以150ms按压反馈为主，不动画画布编辑或键盘操作；减少动效模式关闭位移反馈。节点类型、端口及执行状态同时使用文字呈现，不能只依靠颜色。

### 界面文案维护

用户在重写后要求删除类似“代码通过 DeepSeek API 处理 · 命令逐次审核 · 本机执行，未启用文件与网络隔离”的常驻说明，使界面更简洁。工作台仅保留帮助当前操作的信息，模型调用方式、文件限制、执行环境与恢复边界集中在 [README](../../../../README.md) 中维护。

- 移除顶栏技术横幅、密钥状态徽标和 LOCAL 标识、节点卡片的模型与实现说明、节点库底部的限制清单，以及画布上的重复操作说明。循环节点仍展示最大修复轮数。
- 精简运行设置的介绍、模式副标题与重复规则，历史页的介绍和后台生命周期说明；成功通知使用简短结果，初始状态显示“就绪”，底部不再展示协议版本。
- 保留真实运行未满足的条件、缺少密钥时的配置方法、排除规则重新打开项目才生效的提示，以及输入引用所需的格式与版本信息。
- 审核区域移除通用环境说明句，保留实际运行模式、程序、参数、目录、节点、轮次、版本、用途、预计产物、环境和内容哈希。批准／拒绝操作及其请求体保持原样；删除历史与备份的明确确认继续保留。

后续添加文案时，先判断它是否帮助用户完成当前操作或理解当前结果。避免把 README 的实现说明重复放在常驻面板；错误原因、启动条件、实际审核信息和会造成数据损失的操作确认不能作为冗余说明删除。此次只调整呈现文案和相关样式，不改变执行权限、隔离能力、HTTP 接口、工作流格式或订阅生命周期。

### 历史审计

检索 `.agents/docs` 的 implemented、proposed、rejected 分类后，MVP 实现记录与此次改动部分重叠：复用其画布测量、SSE 和审核边界，互链保存；不吸收或改写原联网与隔离决定。Turbopack 缓存端口记录仅涉及旧缓存故障，与 CSS Modules 加载规则无关，保留原记录。未发现其他主题或布局提案。

## Alternatives considered

- **保留旧布局仅更新视觉**：改动较小，能保留已有位置记忆；用户明确选择全面重组，旧布局仍让运行设置和历史隐藏在表单深处，因此不采用。
- **分步引导界面**：首次使用时更容易理解操作顺序；用户选择画布中心工作台，日常需要反复编辑和调试，因此使用可随时切换的面板。
- **仅深色主题**：样式维护和验收成本更小；用户选择跟随系统双色主题，因此提供系统／浅色／深色三态偏好。

## Consequences

功能位置更清晰，主题及响应式状态独立于执行协议。组件共用一个局部样式模块，减少视觉漂移；业务状态集中持有，因此未来拆分为多个路由时必须明确重新处理草稿及订阅生命周期，不能直接把执行订阅放到可卸载的呈现组件内。

移动端可完整配置、运行、审核和查看结果，但复杂画布仍需平移缩放。此次不新增自动布局、执行隔离或模型供应商。
