# Agent Note: Simple Workflow MVP 真实审查、修复与文件事务

Status: implemented

## Problem

本地多 Agent 工作流需要把可视化流程、真实源码、结构化协作、模型工具请求、命令审核和文件写回连接起来。第一阶段只有合成执行器，无法证明真实模型协议、读取权限、进程取消或文件事务。用户要求继续完成 MVP，并在完成后记录实际实现；同时明确暂缓文件与网络隔离，保留本机逐次审核执行。

本文按首次提出日期 2026-10-14 从原 proposed 重写为实际实现记录，吸收原提案的当前 MVP 要求、接口与验收编号。按用户要求，第一阶段引擎基础和暂缓隔离两篇 implemented 记录也合并至本文；历史阶段单独注明，现行实现以其后的模块和接口说明为准。原个人桌面需求文件是历史需求来源，不是运行依赖。实现源码、可复现测试、示例和报告均位于仓库。本文不把合成响应当作真实联网证据；AC-10 继续延期。新增真实界面的本轮浏览器复验因权限拒绝未完成，具体证据范围见下文。

## Decision

应用在 Linux 上以单用户、单个 Node.js 进程运行 Next.js 本地 WebUI。React Flow 负责编辑与展示，后台严格校验独立版本化格式、串行调度单条活动路径。真实运行使用 DeepSeek 官方稳定端点、按节点独立历史和受校验的工具；修复进入固定文本副本，命令白名单在启动时生成且逐次审核，最终修改由独立文件事务服务应用和撤销。

支持读取、审查、修复、复审、条件、循环和输出七种预置节点，提供完整与仅审查两个模板。第一版不支持任意节点、并行调度、多分支数据汇合、多个修复循环、远程仓库/PR、多供应商、多用户、跨进程执行续跑、自由 Shell、自动依赖安装、符号链接/二进制编辑、独立改权限或重命名工具。

工作副本、范围检查、最小环境和进程组管理不提供宿主文件或网络隔离。相关决定及恢复条件见本文[隔离延期与恢复条件](#隔离延期与恢复条件)。只能用于用户信任的项目和批准的命令。

### 第一阶段引擎基础

本节保留第一阶段交付时的事实，不描述现行真实运行能力。初始仓库只有 Next.js 模板，缺少版本化消息、控制/数据图和串行状态机；直接接入模型会使调度错误、供应商错误及权限缺口难以分别定位，因此先实施图、引擎和合成演练。

第一阶段运行模式固定为 `synthetic`，唯一执行器为 `demoRunner`，不读取真实项目、不调用 DeepSeek、不启动子进程、不应用文件。未配置密钥也能编辑和演练；当时真实运行始终禁用，不能宣称完整 MVP 或 AC-01–AC-18 全部通过。

第一阶段 React Flow 修复保留为维护约束：画布测量尺寸单独保存，只改变选中/尺寸时不重建 Workflow，避免受控节点一直隐藏；运行快照按单调事件序号合并，防止迟到 HTTP 响应覆盖 SSE 的完成状态。控制连线/位置映射到独立持久化格式，输入来源单独配置，不落盘选中、尺寸等临时 UI 状态。

当时已核对 Next.js 16.4.0 Cache Components 与默认 Node runtime，处理器先调用 `connection()` 再捕获错误。生产 Request URL 可能规范化为 localhost，因此来源校验使用已验证回环 Host 和监听端口，避免误拒绝浏览器的 127.0.0.1 Origin。创建演练绑定会话内 requestId 和配置哈希；全局管理器单例避免热重载重复初始化，状态排队落盘，存储失败中断。这些约束由现行 API 延续。

历史验证使用 Node.js 24、pnpm 12，包含单元测试、类型检查、lint、生产构建后的临时目录/随机回环端口 HTTP 测试。覆盖图与版本、默认模板、1/2/5 轮、首个命中/兜底、缺失/失败结果、审核重复/拒绝/过期、取消/迟到工具/快照、权限、存储与重启中断；HTTP 覆盖同源/CSRF、保存、幂等、事件重放、跨会话及导出密钥哨兵。浏览器手动检查完整合成演练、节点可见、合成差异、逐次拒绝和两次独立批准，并修复节点测量与快照顺序问题。此阶段没有真实 DeepSeek、命令、文件事务或隔离验收。

历史构建曾重放旧 Turbopack 端口权限错误；移走旧缓存后连续两次默认构建通过，诊断及结论边界继续保留在[构建缓存故障记录](../bug-fix/2026-10-14-turbopack-cached-port-permission-error.md)。

第一阶段启动前只检索到原 MVP proposed，按部分重叠保留提案，未把待实现的真实能力标为完成。后续真实工具接入时新增权限网关、版本验证、模型和命令 adapter、文件事务，而非直接执行合成审批命令；独立 JSONL、历史、刷新恢复等随后落地。由此保留先合成再真实的实施次序及当时局限，避免用后续交付改写初期事实。

### 隔离延期与恢复条件

原 MVP 将文件与网络隔离作为真实命令前提。2026-10-14 用户选择暂缓容器/操作系统沙箱，同时保留副本内本机进程、白名单和逐次人工审核。该决定最初只同步提案、README 及基础记录，未增加真实执行能力，故当时保留 proposed；本机执行及真实验收完成后转为 implemented，本次统一合并至本文。

当前不实现容器或操作系统沙箱，也不将其作为启动条件；AC-10 保留编号并延期，不计为通过。以下边界继续成立：

- 网关和应用服务只约束自身接口；本机命令及子进程以宿主用户权限运行，可以访问原工作区、其他宿主文件和网络。模型补丁写副本、最终写回经事务服务，不能据此承诺原目录只由应用服务修改。
- 白名单、展示哈希和逐次批准限制应用启动的动作，自动模式同样审核；项目脚本本身可能派生其他程序，批准不证明脚本安全。
- 最小环境不主动传入 API 密钥，HOME/TMP 指向副本；同用户脚本仍可能从宿主配置或其他渠道取得敏感信息。
- 副本范围外源码改动或原基线冲突阻止整批应用；备份、回滚和撤销仅覆盖登记事务，不保证发现、阻止或恢复其他宿主副作用。
- Linux 进程组超时/取消清理组内后代，不控制主动脱离组的程序，不提供 CPU、内存或网络资源隔离。
- 界面、审核和实际报告明确“本机执行，未启用文件与网络隔离”；代码通过 DeepSeek API 处理，源码、日志、差异和备份仍需按敏感材料管理。

AC-03 继续验证应用层越界拒绝，AC-08/09 验证本机逐次审核执行，AC-11–15 验证源码扫描和文件事务；这些证据均不能扩大为系统隔离。验证使用受信临时示例，不开展或宣称“不可信脚本无法逃逸”验收；当前真实测试及界面复验限制见[交付与验证证据](#交付与验证证据)。

原延期方案采用 Linux rootless 容器仅挂载运行副本，移除额外 capabilities，禁止提权和宿主 PID/设备访问，使用只读基础文件系统和受控临时目录，禁网并限制 CPU、内存、进程数及时间。不挂载原工作区、宿主 home、Docker socket 或密钥，模型 API 由宿主后台调用。这是历史设计，尚未提供当前配置或能力。

需要执行不可信项目脚本、承诺限制宿主文件访问或禁止联网时，另立恢复隔离的变更，明确目标平台、后端、运行时、镜像和离线依赖。实际证明宿主哨兵、原工作区、敏感环境和受控网络目标不可访问，并验证子进程、取消与超时后，才恢复 AC-10 验收。不得用合成或当前本机测试替代，也不得仅把本节改为相反决定。

### 工作区、文件范围与版本

工作区由后台打开真实根目录，返回绑定会话的 UUID；客户端不能用任意路径替代授权标识。数据目录必须与项目分离且不能互相包含。目录浏览不跟随目录符号链接，界面同时支持绝对路径输入。

启动固定勾选项、排除规则、Workflow、模式与全部已复制源码基线。副本复制整个未排除的普通文本上下文，`scope` 是初始勾选文本列表，`selection` 保留目录授权，因此目录内可新增/删除符合规则的文本；单选文件只能修改该文件。关联文件可以读取与搜索，但范围外问题只能给建议，不能提交阻塞修复或补丁。运行中的编辑仅影响下次。

默认排除 `.git/`、`node_modules/`、构建/覆盖率目录、`.env*`、密钥/证书与常见二进制。支持每行规则、路径规则、`*`、`**` 与目录后代；`node_modules/`、`.workflow-home/`、`.workflow-tmp/` 始终排除。其他敏感规则可调整，界面提示内容可能送入远端模型。无依赖跟随或安装。

路径必须为规范相对路径，拒绝绝对路径、穿越、空分段和反斜杠。Linux `SafeRoot` 固定根目录身份，父目录以 `O_NOFOLLOW` 打开并通过 `/proc/self/fd` 锚定；实际读写再次检查归属、类型及内容。拒绝符号链接、硬链接、特殊文件及超限/非法 UTF-8 文件。副本严格扫描发现链接或异常类型即失败；原项目扫描跳过不可读取文本，但不会将其复制成可写文件。

内容版本为排序路径/完整文本的 SHA-256。每次读取、搜索、补丁与命令核对当前版本；补丁的 `before` 必须准确匹配。读取记录带节点、路径、版本和行范围；问题必须有当前版本读取证据及有效行号。补丁同步引擎版本，最终差异由后台比较实际副本生成，模型不能自报最终修改。

应用前再比较整个原项目已复制文本基线（包括未勾选上下文和增删），任何变化都停止整批。副本范围外源码改动立即停止命令工具路径并阻止应用；缓存和已排除产物不进入写回。扫描不能检测或撤销所有宿主副作用。

### 图、结构化协作与结束状态

控制边和数据引用独立保存；后台验证唯一读取入口、严格出口数量、有序条件与 fallback、类型及必需输入、可达性、终点、当前轮版本及所有修复至输出路径经过复审。仅允许一个明确由 loop 控制的修复回边；删除该回边后必须无环。条件限 `blockingCount`、`validationComplete`、`testsPassed` 与白名单运算符，首个命中生效，不执行自由表达式。

实际进入修复才增加轮数，默认 1，允许 1–5；达到上限保留剩余问题及停止原因，没有额外修复调用。步骤另有由图大小和轮数计算的有限预算。不同 Agent 使用独立对话，共享经校验的材料、版本、问题与修复结果。问题编号由后台分配，复审保留原编号；漏报原问题时保留为 unconfirmed，不能凭遗漏判通过。

真实工具为 `list_files`、`read_file`、`search`、`request_check`、`submit_result`，只有修复节点拥有 `submit_patch`。输入严格解析，同批工具按返回顺序执行；相同调用 ID 和参数返回缓存结果，不重放副作用，同 ID 不同内容失败。`submit_result` 必须在该批最后；提交截断/错误结构/错版本/错范围/无证据不能结束为通过。

模型自报 validations 被丢弃，实际命令重建验证。必要检查缺失、拒绝或依赖不可用为 `validation_incomplete`；必要检查执行失败及协议/范围/模型失败为 `execution_failed`。修复节点同样受必要验证门禁。正常审查结束为 passed 或 issues_remaining，取消为 cancelled。失败或取消后迟到模型/工具不能改变状态或继续执行。

真实正常结束先进入 finalizing，等待待完成命令证据、汇总实际差异、检查范围，再确认或自动应用。完成与文件状态独立：not_applied、awaiting_confirmation、applied、apply_failed、undone。文件应用失败会将总结果改为 execution_failed，另存 `reviewConclusion` 保留原审查结论和剩余问题；修正外部冲突后再次应用仍重新整批检查，成功才恢复原审查结论。HTTP 重复应用/撤销幂等，不再写一次。

### DeepSeek 协议、预算和费用

请求固定发送到 `https://api.deepseek.com/chat/completions`，模型为 `deepseek-flash`。密钥由服务端 `DEEPSEEK_API_KEY` 读取，不暴露给浏览器或 Workflow，不主动传入检查环境。发送 messages 前再移除已配置密钥，防止它意外出现在项目文本或工具结果中；该脱敏也由协议测试核对。节点配置思考 enabled/disabled，开启时传 reasoning_effort low/high/max，默认 high；输出默认 8192 tokens。

使用非流式原生 HTTP adapter。完整 assistant 消息（包括没有工具的思考轮次和 `reasoning_content`）仅在 Agent 内存历史中回传，之后追加对应 tool_call_id 结果，不落盘原始推理。严格校验响应工具与结果，只接受 stop/tool_calls；length、拒绝及非法 JSON/结构停止。网络/模型失败不伪装成空问题。

| 限额 | 当前值与行为 |
| --- | --- |
| 副本 | 最多 1000 普通文本文件、16 MiB 总文本、1 MiB/文件，超限拒绝建立或继续 |
| 读取/搜索 | 单次 256 KiB，节点读取累计 512 KiB；字面搜索最多 100 命中，标记截断 |
| 输入历史 | 序列化 messages 最多 64 KiB（比初拟 64K tokens 更保守的字节门禁），不会裁剪工具或思考配对历史 |
| 工具/对话 | 每次节点进入最多 20 次工具调用，错误/拒绝/缓存重复也计入；最多 21 轮模型请求 |
| 模型请求 | 每次尝试 120 秒，覆盖响应体；响应最大 4 MiB；429/5xx 最多 3 次尝试、有限退避；连接结果未知不盲目重试 |
| 节点耗时 | 总计 10 分钟，含人工审核等待；超时过期待审记录、中止模型及受管理进程 |
| 命令 | 120 秒；stdout/stderr 各最多 1 MiB，截断可见；TERM 后 500 ms KILL，并在父进程结束时清理组内后代 |
| 服务端规模 | Workflow 最多 50 节点、150 边；每会话一个活动运行，同工作区一个活动运行；进程最多保留 50 运行；工作区登记最多 100 |
| 会话/请求 | 会话 8 小时，HTTP JSON 请求体最多 1 MiB；只接受本地会话和写操作令牌 |
| 保留 | 历史手动保留，无后台按日期删除；成功完成的副本清理，失败/等待确认副本保留 |

每个成功与失败请求尝试记录时间、模型、耗时及实际返回 usage；传输、响应体或 HTTP 重试无 usage 时保留未知，截断有 usage 时仍记录。取消后的已返回用量也进入最终证据，不以缺失记零。报告仅在各类缓存/输出 tokens 都已知且无未知尝试时计算费用范围；按 2026-10-14 价格快照，空闲/高峰输入命中 0.02/0.04、未命中 1/2、输出 4/8 元每百万 tokens。估算为范围，不是账单，不接入账户信息。

### 命令逐次审核与依赖边界

白名单在副本建立时固定：最多 30 个发现的 `.test/.spec.[cm]js/ts` 使用 Node 绝对程序及 `--test <相对路径>`；在可信系统目录找到 npm 时，仅开放 package.json 已声明的 test/check/lint/typecheck/build，参数固定 `run <script> --offline --ignore-scripts`。不执行任意命令字符串；项目脚本自身仍可启动其他程序或联网。npm 脚本声明改动后拒绝旧白名单，必须重新运行。

每次审核绑定运行、节点、轮次、版本、环境标识和完整展示内容哈希；批准只消费一次。前一次批准不授权下一次，自动模式相同。拒绝同版本动作后再次请求仍拒绝，不以新 ID 绕过；取消、断开最后一个 SSE 连接、会话失效及节点超时使 pending 过期。SSE 断开不重启后台执行器。

进程使用 `shell:false`、Linux 独立进程组，工作目录为副本，环境仅含固定 PATH、副本 HOME/TMP、LANG、CI、NODE_ENV 和 npm 离线配置；不会主动注入密钥、NODE_OPTIONS 或原环境。输出记录实际退出码、状态、截断、耗时、前后版本及源码改动。明显缺失模块/程序记录 unavailable，对应缺失验证；其他失败记录 failed。依赖不可用不能推导通过。

不复制 node_modules、不自动安装依赖，当前支持无需第三方包的 Node 示例及无需未准备依赖的脚本；一般框架工程完整检查可能无法完成。未来如需依赖材料，须另行检查可复制类型、链接归属、容量和生命周期，不能悄悄指向原项目依赖。

### 应用事务、回滚、撤销和中断恢复

工作区互斥仅在本进程内约束应用服务。应用检查差异版本、整个原基线、范围和每条 expected 内容，整批预检通过后持久化 0600/fsync JSON 日志及完整原内容，才开始写入。日志自身是备份，包含 root、runId、changes、processed、recovered、原权限及状态。

每个文本写入使用固定父目录内临时文件、fsync、内容再检查和 rename；删除同步父目录。修改保留原权限，新增默认 0644，撤销删除恢复原内容、存在性及权限。多文件不是系统原子事务，外部编辑器或命令不受本进程锁约束；每次目标操作仍核对 expected，但最后检查与 rename 之间不能提供操作系统层面的条件原子替换。

部分应用失败按逆序恢复已写文件，只在目标仍等于本次写入内容时回滚；不覆盖并发编辑。无法完整回滚/撤销则保留 needs_recovery、备份与处理列表，同根后续应用阻断。普通撤销先对整个事务检查当前等于 after，任一冲突整批停止，不能覆盖应用后的编辑。撤销不删除命令产物或恢复登记之外的宿主副作用。

启动将 prepared/applying/rolling_back/undoing 日志改为 needs_recovery，绝不重放。恢复历史优先扫描该运行最新持久事务，不能依赖过时 snapshot.transaction；已 applied/undone 的事务可恢复查看及撤销。存在任何未解决恢复事务的运行不能删除备份。

人工恢复步骤：

1. 停止该项目的新运行和外部编辑，复制事务日志及当前受影响文件作为额外保留材料。
2. 核对 `changes` 的 before/after、`processed`、`recovered` 与实际当前文件。若内容不同于预期，不覆盖，先确认外部编辑。
3. 按预期原内容/存在性逐项恢复，保留 `modes`；不要按整个命令工作目录盲目删除产物。
4. 完整确认后，由本机维护者人工将日志状态改为 rolled_back 或 undone，并记录处理原因；部分恢复继续保留 needs_recovery。界面不提供强制覆盖或自动恢复按钮。
5. 重启服务刷新历史；重新运行会建立新副本、新基线和新审核。日志修改属于人工维护，不是自动断点续跑。

### API、存储、刷新与重试

Next.js 使用已安装 16.4.0 的 Route Handlers 及默认 Node runtime，API 不缓存，响应 no-store。开启 Cache Components 时不增加冲突的 runtime/dynamic 配置；处理器先执行 `connection()` 再捕获业务错误，避免捕获预渲染中断。开发/生产仅绑定 127.0.0.1，校验 Host、端口、Origin/Referer/Sec-Fetch-Site、本地 Cookie 和写操作令牌；不同当前会话不能查看或操作已归属的运行。

| 接口 | 操作 |
| --- | --- |
| `/api/session` | 本地会话、令牌及真实能力/密钥是否配置 |
| `/api/workspaces` GET/POST | 目录浏览/登记真实项目与排除规则 |
| `/api/workflows` GET/PUT、`/validate` POST | 草稿加载/严格保存及图校验 |
| `/api/runs` POST | 严格配置、固定 scope、请求 ID 幂等创建 |
| `/api/runs/[id]`、`/events`、`/report` GET | 快照、SSE 顺序事件重放、Markdown/JSON 下载 |
| `/approval`、`/cancel` POST | 一次性内容绑定审核、幂等取消 |
| `/apply` POST | 需要 currentVersion；重试仍检查副本、基线与全部路径 |
| `/undo` POST、`/retry` POST | 事务撤销；新 requestId 创建全新运行，旧批准不能复用 |
| `/api/history` GET、`/[id]` POST/DELETE | 列表、明确恢复快照、确认 `acknowledgeLossOfUndo:true` 后删除历史及全部备份 |

成功 create 的 requestId 保存为本进程幂等记录，删除后不允许同 ID 重建副作用。存储状态排队原子替换，完成落盘后通知 SSE；存储失败中断并禁止文件应用。报告/快照/API/日志对已配置密钥及常见凭据形式脱敏，客户端不收到原始思考历史。

默认专用目录 `~/.local/share/simple-mutiagent/`，或 `SIMPLE_WORKFLOW_DATA_DIR`。0700 目录、0600 文件；独立保存 workflow、runs、events JSONL、reports Markdown、diffs、私有 baselines、copies、transactions。JSONL 以当前顺序全量原子替换，首版不是外部追加日志服务。日志/报告/基线/备份仍包含源码，应按本地敏感材料管理。

刷新用 localStorage 记录最近运行 ID，优先取当前进程快照或手动历史恢复。后台重启把未完成记录变为 interrupted、审核 expired；不恢复模型、命令或流程。单用户桌面历史在未归属时可由新本机会话明确恢复，不是多用户访问控制。等待确认的副本可重新载入后版本检查应用，副本缺失失败，不重新生成旧修改。

## Alternatives considered

- **先接入真实模型再调试图（第一阶段取舍）**：能更早看到真实审查；但当时无法独立定位调度与供应商问题，原设计还将权限和隔离作为真实命令前提，因此先做合成。后续隔离前提已按用户决定延期，先验证状态机的理由保留。
- **提前把原提案转为 implemented（第一阶段取舍）**：可以减少文档维护；但当时真实工具和端到端尚无证据，因此只记录基础阶段，保留提案。真实验收完成后才迁移，本次合并保留该阶段判断。
- **继续只用合成执行器**：便于快速验证图与异常路径，且没有文件副作用；用户需要真实 MVP，因此保留合成作为测试入口，同时新增独立真实 runner，不能把合成通过当实体验收。
- **直接在原项目修复并复用依赖**：准备简单、检查更容易复用 node_modules；应用提交的补丁会污染原目录、难以整批核对，因此使用文本副本和最终事务。此选择并不能防止获批命令直接访问原文件。
- **完整项目/依赖复制或原依赖链接**：可以运行更多工程测试；递归链接、二进制与容量检查扩张当前文件契约。当前选择无第三方依赖示例及显式 unavailable，不自动安装、不直接链接原依赖；需要框架依赖时另行实施准备契约。
- **通用 Agent 框架、React Flow 对象直接执行**：可减少编排设施开发；权限、版本和应用事务仍需自行约束，画布测量/选中字段也不该落盘。采用独立 schema 和可注入 NodeRunner，React Flow 仅作编辑/展示。
- **兼容 SDK 与流式响应**：有成熟接口且可改善实时文字体验；扩展推理字段及工具拼接需要额外验证。当前选择非流式原生 HTTP，验证完整历史与失败用量；后台事件实时展示节点/工具，首版不展示 token 流。
- **DeepSeek Beta strict**：可降低工具参数格式错误；Beta/受限 schema 仍不能保证文件权限。采用稳定地址、本地严格校验及有限错误预算。
- **只靠提示词约束路径或命令**：集成简单；不可信代码与模型不能承担授权。工具网关、状态机和事务服务独立强制校验。
- **保留系统隔离为真实命令前提**：能同时约束宿主访问和网络，适合不可信脚本；引入用户要求暂缓的容器准备与隔离验收，保留为后续恢复方案。
- **连同真实命令一起延期**：减少副作用，可以先推进静态分析与修复；用户选择保留本机逐次审核，因此继续实施真实命令，必要验证仍需实际执行才可判通过。
- **将副本、白名单和审核视为隔离**：实施轻、流程清楚；这些设施不约束派生进程的系统权限，因此不作这一承诺，保留明确边界与 AC-10 延期。

## Consequences

当前代码已支持真实本地多 Agent 审查、修复、复审、检查、应用和撤销，并具备独立后端门禁、重启历史、运行报告和五场景官方联网证据。当前替代了第一阶段“合成 only”的产品边界；其历史事实及最初取舍仍保留。

应用边界仍有限：仅 Linux、单进程、普通文本及有限副本；一般依赖工程不保证可完整测试，验证缺失不能通过。浏览器复验受权限阻断，新增真实 UI 的手动验收需后续授权。模型审查/修复本身可能不准确，报告与差异用于用户判断，不承诺程序正确性。

本机命令可能访问其他宿主文件、敏感配置和网络，甚至脱离受管理进程组。最小环境不意味着无法读取同用户的密钥；offline 不意味着断网。事务不是系统多文件原子写入，备份及撤销只覆盖登记变更，无法保证全部宿主副作用或外部并发编辑的系统级隔离。AC-10 保持延期，不能借其他 17 项实现将其标为通过。
